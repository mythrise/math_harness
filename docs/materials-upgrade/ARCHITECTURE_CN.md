# Materials Contract Upgrade 0.4.0-rc1

## 基线与发布范围

针对 `mythrise/math_harness@f1ff48beebf7084ada6f16fc135801f484605a52` 的源码扩展。保留已修复的R2文献流程、Claude/GPT接管、冻结评测、Docker执行、PaperKit隔离编译、原始MOSAIC和OurWork。不重写已冻结工作区，不自动提交或推送。

该交付是完整的本轮升级源码，不是完整当前仓库的克隆。当前容器无法通过网络取得全库字节，故不将混合重建的本地测试目录冒充完整最新版。升级后可在用户真实checkout上通过 build_full_source.py 打包完整运行源码。原核心包版本元数据不强行改写；此次扩展和发布版本以 UPGRADE_MANIFEST.json 的 0.4.0-rc1 标识，镜像名称保持原部署兼容。

## 调用链

冻结输入 → 原最高调度者与Exa初查 → 只读开发数据盘点 → 题意分析员与数学审查 → 数据方案员与实验审查 → 建模手候选方案与双职责审查 → 冻结准备合同 → 原建模/文献反方/计划审查 → 正式模式团队签核 → 原独立评测器预检 → 代码手 → 每候选每变体自测 → 开发筛选 → 冻结确认 → 正文 → 摘要编辑员 → 逐问覆盖映射及论文语义审查 → 原隔离XeLaTeX → 原逐页视觉审查/有界返工 → 真实人工签核 → AI详情PDF → 支撑包 → 两文件MD5/SHA256清单。

所有生成/审查仍走 Controller.call / ReviewBoard / Store，不另开一个不受预算约束的模型循环。服务不可用、未知在途、预算耗尽与科研否决沿用不同异常语义。新准备环节用有界反馈修复；有效否定意见不能通过换供应商丢弃。

## 14角色、15技能

在原11角色上增加problem_analyst、data_steward、abstract_editor。现有supervisor、modeler、coder、verifier_author、math_reviewer、experiment_reviewer、paper_reviewer、literature_scout、hypothesis_critic、literature_reviewer、writer继续保留。

role_skills.py将每个角色需要的Skill正文显式载入CLI提示，而不是期待无工具的临时子进程自行发现文件。公共原则与角色Skill放在控制器指令部分；题面、文献和模型返回都放在DATA中。DATA的尖括号编码只是降低边界混淆，不是完整的提示注入证明。

技能文件身份、角色映射进入运行指纹与调用输入摘要。每份回执带skill_digest及文件hash；缺文件、改名、符号链接、超长正文、运行后修改均拒绝。私有实际提示保存到调用目录，权限owner-only，不放进公开支撑包。相同输入重放不重新发送模型调用。

## 新的5种结构合同

- problem_brief：实际Q-ID、输入输出、直接/推断目标、约束与原题[start,end)字符锚点、问题依赖DAG、歧义。定位一致只证明字符串存在，语义是否蕴含仍由独立审查负责。
- data_plan：每个输入的来源与用途、采样单位、分组/时间划分、转换理由和训练折范围、原始数据不可变。合成场景不能声明成观测。
- model_portfolio：每问一个可用基准与按需候选，解释原理、适配、局限、单项变化、验证与停止。参考表条目不能直接当已安装算法。
- paper_map：每问8个内容要素的位置，允许共享章节；推导等确实不适用时给理由，结果/执行/验证不能用N/A逃避。量化结论绑定该问已有claims，定性结论绑定原job的哈希证据。
- abstract_revision：正文完成后只从其claims提炼摘要，不新增结果/引文，不改正文模型；一页原则由实际排版门禁检查，不用任意字数或数字数量替代。

调用 `python -m cumcm_harness.materials_cli schema` 查看新增合同。schemas目录同时保存可读JSON；运行时schema仍在代码中注册。上游CLI的schema枚举未被替换。

## 数据与算法边界

运行前数据模块对CSV做有界只读扫描（默认最多100000行、50MB）：缺失/非有限/数值范围/重复行/解析状态与前后hash。其他格式明确METADATA_ONLY，需后续格式专门核验；不能宣称全附件已做数值EDA。原始数据从不自动改写；学习型预处理依旧由受控求解代码实施，并在独立评测/审查中验证。未实现自动MICE、DBSCAN、跨文件单位推断或对所有格式的万能清洗。

模型XLSX的191行放入来源标注的参考目录。检索只返回最多若干相关卡，状态REFERENCE_ONLY_NOT_EXECUTABLE；原算法库与MOSAIC限制不变。Python教程不自动装载，不把AST可解析当性能验证。

## 论文和图表

源头仍是结构化paper JSON+真实claims。新覆盖检查防止漏问、摘要新增数值、符号不一致。符号表由计划生成；图表的数值仍从实际确认行绘制。OurWork框架图使用原v16 SVG构造能力，但内容改成本题各问和依赖，区别于软件架构图。问题多时聚合显示并保留全量依赖清单，不用缩成看不清的小字。原20个模板及MOSAIC资源不改。

新增绘图检查本地中文字体能力并检查实际渲染缺字，不发字体文件。数字、单位、图注、样本标准差的含义明确。原PaperKit的连续页码/页边距/附录可信边界/缺字/溢出/匿名检查继续保留。没有强制25页或数量配额。

已有稿件模式提供结构化draft/plan/claims的诊断CLI，不自动把任意PDF或DOCX改写成已验收论文。用户资料要求的Word+PDF+LaTeX三格式同期输出，本版只交付LaTeX/PDF与原有支撑包，不声称已实现Word内容同构导出。

## AI披露与提交

用途来自本次真正执行的角色/输入字段/schema/提示摘要回执，而非生成结束后臆造；具体输出用响应摘要绑定。旧数据缺字段如实说明。服务失败或未返回版本不猜模型型号；真实人工采纳、修改、核验仍要求原操作员文件，不由模型生成“已核验”。这份元数据不是人工核验本身。

最终封存仅对已完成的paper.pdf和support.zip生成哈希；manifest在ZIP之外，避免自哈希循环。客户端MD5提交和后续上传仍由人操作；任何字节变化必须重新核对。正式参赛不能以练习模式的自动完成状态替代人工门禁。
