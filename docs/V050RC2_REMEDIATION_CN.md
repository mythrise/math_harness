## 初版覆盖与基线

`source_units` 按分句提供原文位置；模型必须逐项填写 `coverage`，状态为 EXTRACTED/MERGED/EXCLUDED/NEEDS_READING、关联条目和理由。漏行、假锚点、用第一条建议覆盖后续约束均拒绝。NEEDS_READING 留存待读账本并停止推进。字符覆盖只证明定位完整，反方仍必须核对每项含义。

独立 portfolio 为每问生成规范基线 ID、原选项摘要和 portfolio 摘要。最终计划的 `baseline_binding` 逐问 KEEP 或 REPLACE，`baseline` 文本与规范描述一致。KEEP 不能修改描述或方法；REPLACE 必须解释适用性与比较强度，并经过额外数学/实验双角色独立审查。求解器 `baseline_implementation` 绑定计划摘要、baseline variant 和实际源文件位置；源代码审查必须核对真实实现，元数据不是算法正确性的证明。冻结协议和每项实验回执携带绑定摘要和实际代码摘要。

未决事项必须有 ID、严重性、影响阶段、关联条目、问题和解决动作。关键事项不能标记暂缓；达到其影响阶段前阻断，需要澄清后的新输入工作区。非关键事项可明确暂缓，不能从报告消失。

## 文字与版式

保留原数值/公式/引用 token 检查，并增加按科学分句保留实体与关系顺序的保守约束。允许完整分句重排和有限明确的语法改写；更宽泛改写可能被拒绝，应提交较小的含义保持修改，再由独立审查确认。该检查不证明原稿科学结论正确。

实际修改稿先落在摘要绑定的 `revision_prepared/`，再由隔离 TeX 或带 Writer + Math 的独立文档镜像渲染。容器无网络，只挂载暂存输入、固定渲染代码和输出，不挂载凭证或仓库。输出报告比较实际 PDF 技术 token、公式可见性、页数、页面越界和乱码，并对原稿/改稿逐页进行独立视觉审查。只有这一实际渲染证据进入签核目标；CI 样例不能替代当前文档。

缺工具、编译失败或版式未通过，只发布 `DRAFT_PENDING_LAYOUT` 编辑副本，明确 `contest_ready=false`；不请求可提交文档的发布签核。未知渲染进程必须先核对，不能自动重试。所有科学性修改继续输出 `research_handoff.md` 并进入新 idea 工作区。
