# Claude 调用不设本地等待时限

根据用户要求，Claude 默认使用 `claude_timeout: null`：控制器和 CLI 适配器持续等待进程正常返回或明确失败，不因经过 180 秒或 600 秒终止调用。数学审查、实验审查、反方、验证器生成和论文修订共用该策略。

`review_timeout` 与 `model_timeout` 继续控制 Codex；Docker 实验、TeX、Exa 的边界保持各自原有语义。Claude 如需用户主动设定有限等待，可单独配置正且有限的 `claude_timeout`，不会再被通用审查时限压低。直接创建 `CLIProvider('claude')` 同样默认无时限。

进程回执明确记录 `timeout_seconds: null`。无时限不意味着成功：进程异常退出、远端明确报错、无效响应或有效科学否决仍按真实结果记录。尚在运行时不触发服务接管；人工中断仍清理本次子进程，并按原有未知状态规则核对后续恢复。

本策略用于新版本和新工作区。旧冻结工作区的配置、调用、超时和审查回执不改写。当前源码受版本指纹保护，不能借此重写旧运行记录。

回归包括：时钟超过旧 180/600 秒上限仍继续等待；正常/非零退出；人工中断清理；研究和修订控制器；Claude 不被 review_timeout 二次截断；Codex/实验有限超时保持有效。以上回归是基础设施测试，不是实际数学题通过证据。

模型服务和本地转发器属于额外一层；它们明确返回的网络/服务错误仍是真实失败，Harness 不把这类失败改成成功。

本机 `127.0.0.1:8462` 转发器也已为 Claude 请求取消原 300 秒等待上限，保留其他模型路由原设置。通过检查无 TCP 客户端连接后重载服务，不中断在途调用。Claude CLI 自身或远端返回的明确网络/服务错误仍会如实记录；不修改闭源 CLI。
