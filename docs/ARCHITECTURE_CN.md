# CUMCM-EgoHarness：全链路设计与代码对应

版本0.5.0-rc3；工程架构更新日期：2026-09-10。原研究与规则核验日期：2026-09-05。

## 一、目标不是“自动凑一篇论文”

系统的交付对象是一个可追溯的建模研究包：问题理解、假设与方程、代码、计算结果、独立核验、消融与敏感性、有限范围内的统计结论、论文及复现材料。漂亮的语言不能替代模型正确性；代码正常退出不能替代独立验证；测试夹具不能替代真实 Claude 审查。

本版本追求比单纯提示词链更强的工程可靠性，但没有四个上游系统同预算比赛题比较结果，所以没有“已超过全部数学建模Agent”的结论。`benchmarks/status.json` 将这一点编码为未完成，而不是把缺测记成零分。

新增资料合同层的输入、输出、冻结与审查接入点见 [0.4 接入说明](MATERIALS_V040_INTEGRATION_CN.md)。显式启用后，题面合同、开发数据审计及方法组合在原模型前完成审查；正文完成后再生成摘要和逐问覆盖映射，最后按实际 PDF/ZIP 字节封存。

三模式入口见 [0.5 接入说明](THREE_INPUT_V050_INTEGRATION_CN.md)。`entry_inputs` 冻结模式与独立材料；`idea_workflow` 在盲题意/数据/基准审查后提取和反审初版，再绑定到原计划任务与假设；`paper_revision` 复用调用账本与独立审查，导出文字修订和新研究交接材料，不进入旧实验的结果表。

rc3 的 `source-ledger-v1` 在 PI 与 Exa 之前冻结原件和原页，并经过逐页视觉核对、来源批次提取、类型化整合、局部补丁及逐问/全局审查。通过后把已核对的来源投影传给后续建模和审查；此门不认证求解和实验。详细合同与回放边界见 [来源通道说明](BRIEF_RC3_CN.md)。

## 二、总体架构

```
最高调度者 Research PI（Codex）
   ├─ 文献研究员 → Exa 抽象查询 → 假设卡 → 独立反方反例检索
   ├─ 建模手（Codex）：题意 → 假设 → 数学模型 → 子任务 DAG
   ├─ 代码手（Codex）：代码版本 → 基准/候选/消融/敏感性
   ├─ 论文手（Codex）：已验证主张 → 中文论文 → 图表
   └─ 独立审查组
       ├─ 评测器作者 / 假设反方（Claude 优先，终止性故障可由 Codex 接管）
       ├─ 文献 / 数学 / 实验审查员（每职责 Claude + Codex 双席）
       └─ 论文/渲染审查员（Codex 双席，当前仅此适配器支持图片）
             ↓ 必须服从，不能覆盖
确定性内核：JSON Schema / DAG / 内容哈希 / SQLite / 一次性运行许可
             ↓
执行层：并行实验单元 / 只读输入 / Docker / 时间与资源上限
             ↓
开发阶段选择 → 冻结候选 → 独立确认 → 主张证据表
             ↓
OurWork SVG → XeLaTeX → 源码附录 → AI详情 → 人工签核 → 本地发布
```

PI 能提议停止、修改研究方向、要求返工；不能修改已冻结评测器、伪造 Claude PASS、改变确认指标、绕过人工签核。每个角色有独立本地 SQLite 与 `FOCUS.md`，它们是阶段回执的投影，不是事实权威，也不保存模型隐藏推理。

`configs/exa-resilient.json` 显式启用 Exa；旧 profile 与缺省配置保持本地文献模式。每条模型假设对应唯一假设卡，反方必须检索反例，精确引文与来源摘要由程序校验。双席文献审查后才接受参考文献，经验性/简化假设的 `hypothesis_Hn` 诊断必须在执行阶段实际通过。搜索结果和诊断通过均不证明现实假设为真。接口、缓存、隐私和恢复细节见 `docs/EXA_RESILIENT_REVIEW_CN.md`。

Exa R2 在显式 sidecar 下使用 `exa_policy → exa_authorization → exa_transport/exa_ledger → exa_evidence → literature_r2`：冻结研究范围、逐尝试计数、保存版本快照，再将逐假设文献对抗接入原审查与执行门禁。无 sidecar 保持旧适配器。配置、缓存、恢复和 contest 授权见 [R2 说明](EXA_R2_CN.md)。

## 三、从题目到模型合同

`intake.py` 首先复制并散列题面和数据，保存 CSV 形状、缺失值、有限预览、JSON 结构、Excel 表名及公式风险。评测私有数据只给模型看结构，不把标签内容交给代码手。确认数据不参与开发提示包。原始图表的语义需要人工/外部核实，当前 PDF 导入不是通用视觉理解器。

建模合同不是一句“用遗传算法求解”。`contracts.py` 中 Plan 要求：

| 字段 | 含义与门禁 |
|---|---|
| questions | 每一问的验收条件、指标、单位，不能漏问 |
| assumptions / variables / equations / constraints | 假设依据、变量含义、数学表达和可行域 |
| tasks | 可拓扑排序的子任务依赖图；拒绝循环、重名、未知依赖 |
| baseline | 简单、可解释、可以被独立复现的基准 |
| ablations / sensitivity | 有实际变化定义的消融和灵敏度，不能只改名称 |
| evaluator_spec | 独立核验应该如何从原始输出重算 |
| resources | CPU、内存、时间、分片/检查点和不变数据预计算声明 |

任务 DAG 是建模合同的依赖表示，当前代码手输出一个统一的 Python 求解入口，入口内部实现各子任务；**不是为每个 DAG 节点动态生成一个独立容器**。研究实验单元在外层并行。对于超大任务，应先把可独立执行的单元显式编码到问题适配器。

算法检索保留十类方法卡的确定性关键词排序，0.3.0 的 `algorithm_library.enrich_method` 为每一族提供已实现的 CPU 入口、旧入口、适用条件与校验要求。`select_algorithms` 只做部分结构筛选，最终仍须问题合同、实现与执行门禁核验。新增 `algopt`、`algpredict`、`algdecision`、`alggraph`、`algscience` 对应优化、预测、评价、图算法及数值/统计工具；MOSAIC 直接调用附件原码，原有表示与预算约束继续传给模型。旧 `linear_fit/linear_forecast/topsis` 函数未改。

`algpromotion` 是消费可信控制器记录的独立比较工具，不会替代研究内核、审查板或人工签核，不自动晋级任何算法。外部模型目录只提供来源和未执行状态，没有下载权重或伪装的运行入口。算法完整接口、限制和负结果见 `docs/algorithm-upgrade/`。

文献证据仅能引用当前 `sources[]` 的 ID 与精确原文；题目定义、方法卡和冻结实验合同作为不同权限的上下文，不能冒充文献引用。文献失败的完整 dossier 存入内容寻址对象库，返工包保留每轮审查意见、引文、假设检验和来源摘要，但不重复文献全文，只附最新方案一次。CLI 在启动外部进程前同时检查字符与字节上限；超长输入及直接提供方失败停止本轮，避免相同错误继续消耗返工次数。否定结论与所有完整记录仍保留。

## 四、定制 MOSAIC skill

入口：`.agents/skills/mosaic-multiobjective/SKILL.md` 和 `cumcm_harness/algorithms.py`。

本交付没有把附件替换成 NSGA-II 或通用 GA。`mosaic_solve()` 调用 `vendor/mosaic_v14/mosaic_solve.py`；原始文件由408项供应清单共同校验。包装层检查实际付费评价数 `ledger.spent`、结果评价数与预算一致。

对向量目标最小化问题：

\[
\min_{x\in\mathcal X} F(x)=(f_1(x),\ldots,f_m(x)),\qquad N_{FE}\le B.
\]

这里每次真实目标评价进入账本，代理打分不能伪装成目标评价，纯结构缓存不得偷存目标值。返回前沿中的每个点必须来自账本。适用性必须明确到表示、目标个数、确定性、约束和 codec 类型。

| 分支 | 正确定位 |
|---|---|
| incumbent | 保留原始默认调度，包括旧版连续盒约束回退；不是全部都只能处理离散序列 |
| incumbent_cached | 原便宜基线的结构加速分支，只有附件认证的 codec |
| fast_h0 | 对双目标、确定性、ordered-subset、指定 codec 的 v13-H0 工程加速 |
| local24 / refit32 | 研究分支；需要显式 opt-in，不自动成为生产默认 |

不支持的问题应明确报告不适用，建立单独且经过验证的适配器；不能把任意一般约束罚函数或整数四舍五入冒充原算法能力。没有新增神经 MoE 训练，也没有证明普适 SOTA。

演示消融 `mosaic_infill_ablation` 使用相同引擎与配置，只把 `enabled` 开关置为False；这与“整个优化器换成随机搜索”的基准对比不同。灵敏度只把种群规模改为16，其余预算保持一致。研究候选 c1 改用 refit32，允许改进、无效或负结果。

## 五、确定性 autoresearch

### 评测器冻结前执行验收

真实运行的评测器包必须提供独立入口 `test_evaluator.py`。控制器在冻结评测协议之前，通过 Docker 执行有界基础测试，并分别提供缺失答案、畸形 JSON 和伪造高分答案检查拒绝行为。基础测试必须至少包含三个不同的实质性正例、负例或边界案例；进程退出成功不能替代 `tests.json` 中逐项通过。

已确定退出的失败程序及其日志作为结构化返工反馈，连同对应源码交回评测器作者。每个源码摘要有独立测试目录；旧失败输出不覆盖。未知 RUNNING、Docker 缺失及模型传输失败不作为代码问题自动重试。通过基础测试后，完整模型合同、源码和有界执行回执一起交给数学与实验 Claude CLI 审查。此流程不能认证正式镜场精度、优化效果或完整确认矩阵；这些仍由后续阶段检验。

该入口只在真实模型流程启用，随包演示夹具继续使用原有演示验收路径。实现位于 `cumcm_harness/verifier_preflight.py` 与 `Controller.produce_reviewed`。

### 5.1 什么叫确定性

不是承诺 Codex 或 Claude 每次生成相同文本，也不是承诺 GPU 在所有机器上逐位一致。这里固定的是：已经接受的计划、代码快照、评测器、数据、资源、随机种子、依赖关系、状态转移、结果发布和选择规则。

运行单元近似由以下内容定义：

\[
ID=H(\text{candidate},H(code),H(evaluator),phase,seed,variant,H(protocol),H(data),H(environment),backend).
\]

同一个 ID 不得重复发起未知状态的任务。完成单元只有输出文件完整且哈希匹配才可复用；失败与未知不会被解释为成功。包发布也有按摘要的操作系统锁，避免并行单元首次写入相同 staging 目录。

### 5.2 开发与确认

先冻结指标方向、最小有意义效应、开发种子、确认种子、FE预算、候选数和评测器。用开发集挑候选；开发的消融与敏感性只能做诊断，不可混进主方法平均值。基准在精确平局时获选。

只有被选中的候选与原始基准进入确认阶段。确认数据不反哺下一轮候选选择；当前协议结束后再研究必须新建协议与新的独立确认单元，不能反复查看同一确认集直至显著。

对配对重复结果定义改进量：

\[
d_i=s_i^{candidate}-s_i^{baseline}
\]

最大化指标用上式，最小化指标反号。固定 bootstrap RNG 对配对改进量重采样，计算95%百分位区间。少于五个配对单元直接标记不充分；区间下界大于预注册最小效应才保留候选，否则保留基准或给出不确定。五个随机种子只是最小工程演示，不能作为充分的跨题泛化证据。

没有独立确认目录时，记录 `SEED_REPLICATION_SAME_INSTANCE`。随机种子不同不等于数据集独立，也不等于五道不同赛题。开发试验越多，越需要独立确认；不允许把每个消融的偶然优势逐个宣称显著。

### 5.3 失败、修复和停止

初始求解链出现可诊断错误，可在固定评测器下让代码手生成一个新的代码版本，再进行新的审查与试跑，修复轮数有上限。不会修改旧代码包。开发候选失败时保存尝试并排除该候选，不能只挑它成功的种子。确认期失败直接阻塞，不把确认结果拿去指导修复。

超时、未知外部进程或费用可能已经发生的模型调用需要操作员显式恢复。`recover-step` 与 `recover-job` 保留审计原因和旧尝试，不自动删除账单证据。`RUNNING` 不是 checkpoint。长任务的 checkpoint/shard 当前是被审查的合同声明，系统不会自动改造任意脚本实现行内并行。

PI 可以发出“一次可证伪修改”的提议；核心规定何时可执行、何时接纳。阶段经验只写入项目范围，尚未被独立任务验证的“成功经验”不会自动升级成全局算法 skill。

## 六、独立评测与审查

评测器作者只看题目、模型合同和评测规范，不复用代码手的目标函数实现。执行时求解器看公开数据，评测器另行挂载公开与私有参考数据。评测器不能仅回传 solver.answer 中的 `score`。

每个合格结果必须包含有效性、主指标、逐项约束检查、每问覆盖与带单位的测量值。系统用空答案、伪造高分答案做负控制；评测器必须明确输出 `valid=false`。评测器崩溃不是“负控制通过”。独立测试还至少包括正确样例、错误答案和边界案例；这些仍不能证明一般正确性，必须由领域审查补足。

审查按职责设独立席位，默认每职责两席。文献、数学与实验审查以 Claude 为首席、Codex 为交叉检查席；已终止的传输/格式故障可以有限重试并由另一个 provider 接管。论文图像审查使用两次 Codex 图片调用。彼此不共享会话，不把“作者已经认为正确”作为输入。每份回执绑定确切 artifact digest，有效否定意见、P0/P1、必要检查未知或摘要异常均不能靠换模型通过。

`review_board.py` 保存成功与否定回执、调用意图、有限重试和熔断状态。恢复复用同一证据的席位，无法通过换父任务名重新投票；未知 RUNNING 必须先核对外部进程并显式恢复。两家都不可用时控制器保留已有实验并记录 `WAITING_REVIEW_PROVIDERS`。同模型接管明确标记降级，不冒称双模型独立证据。

多个同模型的新会话可以减轻上下文锚定，**不是统计独立性证明**。模型审查仍可能共同犯错。精确小规模 oracle、形式约束、替代实现和真实人工检查才是互补证据。本版本不把审查员自然语言的 PASS 当成唯一正确性来源。

## 七、权限和资源

真实模型只生成受限 JSON 文件包，不直接启动宿主机 shell。Codex exec 采用只读、禁止工具/网络搜索的配置；Claude 使用 safe-mode 和 user 配置来源保留本机认证，显式禁止内置工具和 MCP。所有配置都有实际 CLI 版本回执，缺关键能力就阻塞，不降级为 `--yolo`。

生成代码仅由 Docker 后端执行：只读代码与输入、独立可写输出、禁网、非root UID、丢弃 capabilities、禁止提权、CPU/内存/进程/输出/时间限制。评测器与求解器分别执行。Docker 本身在本环境未实测，需要部署机器独立验收；标准容器也不是对所有内核漏洞的安全证明。

可信本地执行仅用于随包代码/测试夹具的内容白名单，不是安全沙箱。不能给未知生成代码加上“trusted”来绕过 Docker。

每个实验工作进程限制内部 BLAS/OMP 线程，满足 `workers × threads ≤ CPU总预算`。长期任务还必须声明行分片与检查点。不变数据预计算由合同要求、评审核验；不是已经实现针对任意国赛数据的通用分片编译器。当前版本没有 GPU 分配器或跨机集群队列。

## 八、论文和绘图

论文手只能引用 `claims.json` 已核验数值。正文的 `{{claim:ID}}` 由程序替换；测量数字直接写入普通段落会被拒绝。数学常数放在公式字段。`{{cite:ID}}` 必须来自已核验文献，并与参考文献集合一致。来源可由操作员导入，或由 Exa 快照、精确引文检查及独立文献审查共同接受；程序不伪称在线核实了每个 DOI。接受的假设合同与实际诊断报告一并进入写作输入和支撑包。

“OurWork”使用附件 v16 引擎。原始二十个模板保留，空编辑必须字节一致；新系统总览图用附件的 SVG/node/arrow 原语组合，导出 SVG、PDF、PNG。新组合不会声称是某个原模板的精确复刻。参考模板的图片槽位仍可接 auto_images、cover/contain 和裁剪；包含照片的 SVG 本来就是矢量与位图混合。

统计图来自冻结的实际分数；误差棒明确是样本标准差，不冒充置信区间。全文用 XeLaTeX 实际编译，缺字、未定义引用、摘要超页、匿名规则或文件大小不合格即阻塞。本机曾发现 pypdf 对中文字体映射的文本提取不正确，已改为 PyMuPDF 做验收文本读取，并保留实际渲染检查，不使用 OCR 猜字。

附录包括生成代码、实际上被加载的定制算法依赖及Python审计事件观测到的运行资源、独立评测器、复现脚本及支撑文件清单。因此演示论文有很长的源码附录；这不是超过正文30页限制。最终人类仍必须阅读与核验完整附录。论文模型审查覆盖全部正文与抽样附录，不冒充逐页AI视觉检查全部代码页。

## 九、2026 合规模式

本模板是根据官方2026格式要求自行实现的排版 profile，**不是组委会发布的官方 LaTeX 类**。官方没有统一限定字体/字号/行距/颜色；赛区的附加要求仍需人工确认。

电子稿从摘要开始、没有承诺页/编号页/目录，正文最多30页，附录含完整可运行源码；A4，四边至少25mm；电子论文不压缩且≤20MB；支撑包≤20MB，含 AI工具使用详情.pdf；参考文献前设置 AI工具使用声明；全文及所有支撑文件不得出现队员、学校、赛区身份信息。

2026年9月1日试行的规则明确要求团队主导核心建模并逐项人工审查AI成果。因此 practice 可以无人值守训练，contest 只能在真实团队审查之间推进。不会生成伪造“人工已核验”，也没有自动上传提交功能。

## 十、与 EgoAgentOS 的关系

沿用 Deterministic Core + LLM Residual、研究计划编译、每角色记忆投影、资源门禁、一次性许可与证据闭环，而不是复制其生产部署并假称已接通云服务。当前权威存储为本地 SQLite。`ego_bridge.py` 提供显式启用的 stage-commit 回执桥；默认无网络操作。没有声称实现了完整的 RXP 线协议或已连接 Nexa/Tencent Agent Memory。

实际数据隔离是工作区加角色，不是多租户生产平台。SQLite/hash链发现误改、陈旧产物与部分破坏；拥有整个宿主机和数据库的恶意管理员仍能重写全部链条。高要求部署要用分离操作员账户、受保护凭证、远程签名锚与专用沙箱，这些不包含在本次实测范围内。

运行期资源也进入复现清单。Python审计钩子不是安全沙箱，原生库直接I/O可能不触发Python事件；因此必须实际解压支撑包在仓库外重跑，不能仅凭清单称完整。
